# 运行时多实例注册表 · 实施说明（v0.1.3）

> 本文是 `multi-instance-design.md`（P3 设计蓝图）的**运行时落地说明**。
> 配套可运行参考实现：`app/multi_instance.py`，单测：`tests/test_multi_instance.py`。
>
> 🔴 **隐私**：本文所有地址、端口、Key 均为占位/示例，不含任何真实部署信息。
> 线上真源含个人凭据，**绝不整文件复制进本仓库**（见 ROADMAP §2 / §5）。

## 1. 要解决的问题

原实现把媒体服务器当作**写死的两台**（`emby` / `emby_adult`），实例名分布在 20+ 处代码里。
用户新增第 3 台时，实时观看、播放记录、排行榜、来源筛选、总览卡片都不会自动出现，
必须逐处改代码 —— 不具备商业化交付能力。

目标：**一处注册、全模块派生**。用户在面板点「➕ 媒体服务器」填完地址与 Key，
保存即生效（缓存 3 秒），无需改代码、无需重启容器、无需人工提醒。

## 2. 数据模型

```jsonc
// 新增实例存独立 JSON（与主配置隔离 → 升级零变更）
// <data_dir>/emby_instances.json
{
  "instances": [
    {
      "id": "emby_third",              // 服务端生成/清洗，唯一，不可为 emby / emby_adult
      "name": "Third",                 // 显示名
      "short": "third",                // 播放记录库/来源标签的短键
      "addr": "host.docker.internal",  // 地址
      "port": 8097,                    // 端口
      "api_key": "<用户填写>",          // 落盘保存，前端只见打码值
      "cname": "",                     // 可选：容器名（用于资源占用行）
      "pr_db_path": "",                // 可选：播放记录库路径，留空走活动日志兜底
      "enabled": true
    }
  ]
}
```

**兼容铁律（商用化零变更）**：旧配置的成对内置键不迁移、不改写、不删除，
读取时自动折算为注册表前两项：

| 实例 id | short | 旧配置键 | 说明 |
|---|---|---|---|
| `emby` | `main` | `emby_key` + 服务注册表 `emby` | 主实例 |
| `emby_adult` | `adult` | `emby_key2` + 服务注册表 `emby_adult` | 第二实例 |

若用户从未配置第二台，该项仍保留（Key 为空 → 接口探测自动跳过，不影响其它实例）。

## 3. API 契约

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/emby/instances` | GET | `{ok, instances: [...脱敏...], extra: [...打码...]}`；`instances` 供前端下拉/筛选/总览卡使用 |
| `/api/emby/instances/save` | POST | `{instances:[新增实例...]}` → 保存并使缓存失效；返回最新脱敏清单 |
| `/api/emby/instances/test` | POST | `{id}` → 单实例连通测试（返回 ServerName / Version） |
| `/api/emby/servers` | GET | 总览统计；`servers[]` 与 `instances[]` 均按注册表动态生成 |
| `/api/emby/sessions` | GET | 实时观看；`sessions[]` 带 `server` / `server_key` / `mt_full_name`，另带 `instances[]` |
| `/api/emby/plays?server=<id\|all>` | GET | 播放记录；`all` 时按注册表逐台聚合并合并分页，`parts` 按 short 逐台列出 |
| `/api/emby/rank?server=<id\|all>` | GET | 排行榜；同上，`parts` 按 short 逐台列出 |

**凭据安全**：
- `public()` / `extra_public()` 永不输出明文 `api_key`，只给 `has_key`；表单里显示 `********`。
- 保存时若收到打码值或空值，后端**保留该 id 原有 Key**，编辑不会把凭据洗掉。
- 前端实例管理弹窗不依赖任何外部 CSS 类，全部 inline style，便于不同基线接入。

## 4. 自动派生矩阵（线上已实机验证）

| 模块 | 改造前 | 改造后 | 验证方式 |
|---|---|---|---|
| 实时观看会话 | 写死两台并发拉取 | 遍历注册表，并发数自适应 | 新增第 3 台后 `instances` 变 3 |
| 总览统计卡片 | 模块加载期静态常量 2 台 | 运行时动态求值 | 新增后 `servers` 出第 3 张卡 |
| 播放记录 | 合并只加总两台 | 逐台聚合 + 合并分页 | `parts` 自动多出 `probe` |
| 排行榜 | 合并只加总两台 | 逐台聚合 + 按用户合并重排 | `parts` 自动多出 `probe` |
| 播放记录实例下拉 | 3 个写死 option | 按注册表生成 | 新增后自动出现 |
| 实时观看来源筛选条 | 写死 KFC / KFC2 按钮 | 按注册表生成 +「➕ 媒体服务器」 | — |
| 来源徽标 | 二元配色 | 按实例序号 4 色循环 | — |
| Emby 管理页切换按钮 | 写死两个按钮 | 按注册表生成 | — |
| 图片扫描实例列表 | 写死两台 | 遍历注册表 | — |
| 速度测试 | 写死两台 | 遍历注册表 | — |
| 动作分发 `/api/action` | 只注册两台 | 运行时惰性注册新增实例 | 新实例动作返回业务错误而非 500 |
| 播放记录库路径表 | 只有 main / adult | 每实例一份 | — |

**端到端实测（线上）**：新增一台不可达探针实例后 ——
`/api/emby/instances` 由 2→3、`/api/emby/servers` 出第 3 张卡、
`rank` / `plays` 的 `parts` 自动多出该实例；动作端点走 `act_emby` 返回业务错误而非崩溃；
删除探针后 1:1 还原为 2 台。凭据打码与「打码回存不丢 Key」均通过。

## 5. 实时观看卡片（本轮同批优化）

- 单会话时卡片不再被 `1fr` 拉满整行（`minmax(380px,620px)`），消除海报右侧大片空白。
- 右侧信息区由垂直居中改为顶部对齐；片名 + 用户名 + TG 头像/ID 明确排在封面右侧。
- 新增 **`mt_full_name`**：从会话的 `Path` / `MediaSources[].Path` 提取整理后的完整文件名
  （含分辨率、动态范围 Profile、码率、来源等），在右侧单行展示并支持悬停看全文。
- 动态范围沿用 v0.1.2 的「文件名优先 + Emby 字段兜底」解析，支持
  `Dolby Vision P4/P5/P7/P8`、`HDR10+`、`HDR10`、`HLG`、`SDR`。

## 6. 发布副本接入步骤（给维护者）

发布副本目前仍是**单实例旧基线**（v0.1.1 起的脱敏快照），与线上 V1.46 不是同一版本。
本仓库本轮提供的是**可直接单测的参考模块 + 本文档**，不整文件覆盖线上真源（防凭据外泄）。

接入顺序（每步 `py_compile` + 接口实测）：

1. 在 `app.py` 配置读取之后实例化 `InstanceRegistry`（`cfg` / `containers` 换成本项目的读取函数）。
2. 把所有「取地址 / 取 Key / 遍历实例」的调用改为 `registry.conf(which)` / `registry.key(which)` / `registry.all()`。
3. 按 §3 增加 3 个 API 端点；`sessions` / `servers` 响应体带上 `instances`。
4. 前端把写死的实例按钮、下拉 option、筛选条改为遍历 `instances`；加实例管理弹窗。
5. 逐项对照 §4 矩阵验收；新增一台测试实例验证自动派生后**删除还原**。
6. 全程过 `tools/privacy_scan.py`，`blocking=0` 才允许提交/推送。

## 7. 已知边界

- **播报（TG 入库/求片通知）** 属 PT 链路全局事件，不按媒体服务器实例分库；
  实例维度体现在「来源标签 / 播放记录 / 排行 / 总览 / 筛选」上，播报本体仍是一条全局流水。
- **洗版槽位对照** 目前仍是「该片在两台库内的版本」语义，按 N 台展开需要单独一轮数据模型调整。
- 新增实例若未填播放库路径，播放记录自动降级到 Emby 官方活动日志（只读，绝不写）。
- 缓存 3 秒：保存后最多 3 秒全模块生效；总览统计另有 12 秒缓存，保存时已主动失效。
